# 舞台走位校验系统

一款舞台走位（Blocking）校验 Web 应用：在「舞台区域连接图」上标注各区域间的通行耗时、**通道容量**与**通道封闭时段**，为演员按时间下达「到位口令」（可带**停留时长**），系统从上一口令时刻出发**逐边推演**相邻口令之间的实际行进过程——进入连接若与封闭时段重叠，会在区域**原地等待**或**自动改走其他路径**，据此计算**最早到达时刻**并标出**无法按时抵达**的区段；两种走位模式算出逐边路线后，还会汇总所有演员对同一无向连接的**占用区间**做**通道占用冲突**校验，支持编辑后即时重算与一键导出 Markdown 校验报告。还可在当前校验模式下保存**走位方案基线快照**，编辑后即时对照基线列出新增 / 移除区段及状态、迟到、路线、通道冲突的变化。新增**应急疏散快照**：输入事件时刻并选择出口区域，按当前校验模式的实际路线还原每位演员当时的位置并计算最早疏散路线，页面按最晚撤离优先展示，报告追加同一快照。还支持**跨演员口令依赖**：在两条口令之间维护「前置完成后至少等待 N 秒才可执行后置」的有向约束，保存前检查整张依赖图（成环拒绝写入并返回口令链），校验时按当前模式的实际时刻列出满足 / 违约 / 无法判定，Markdown 报告追加依赖汇总与明细。

内置两种校验模式，可在结果区一键切换：

- **连续口令延误传导**（默认）：首条口令视为准时到位，之后逐段连续推演——实际出发时刻取「计划时刻与实际到达时刻的较晚值」再加停留时长，**某段迟到会传导给后续区段**，后续间隔充足时可**吸收延误、恢复准时**；
- **区段独立校验**：每段均从上一口令计划时刻出发，段与段互不影响（即旧版行为）。

技术栈：Node.js + Express + 原生 HTML/CSS/JavaScript（无任何前端构建步骤）。

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后访问：**http://localhost:3000**（容器内服务端口 `3000`，Compose 默认映射到主机 `3000` 端口）

> 首次启动时，若数据文件不存在，系统会自动写入内置示例数据（9 个舞台区域、11 条连接——其中 2 条带封闭时段、1 条容量为 2、3 位演员、12 条口令、3 条跨演员口令依赖，含刻意设计的「等待」「绕行」「超时」「不可达」「停留导致迟到 → 延误传导 → 间隔吸收恢复准时」、两位演员并发占用「通道占用冲突」以及依赖「满足 / 违约 / 无法判定」演示数据）。

## 配置项

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | Web 服务监听端口（Compose 中映射为主机 3000 端口） |
| `DATA_DIR` | `./data`（容器内 `/app/data`） | 数据文件 `data.json` 存放目录 |

Compose 默认将数据目录挂载为命名卷 `stage-data` 以持久化修改；执行 `docker compose down -v` 删除卷后重启即可恢复示例数据（也可在页面右上角点击「恢复示例数据」）。

## 本地开发（不用 Docker）

```bash
npm install
npm start
# 访问 http://localhost:3000
```

要求 Node.js ≥ 18。

## 功能说明

- **舞台区域**：维护区域名称与备注（如 舞台中央、侧台右、后台化妆间）。
- **区域连接**：维护无向连接、通行耗时（秒）、**通道容量**（同一时刻允许并发占用的人数，1～10，缺省 1）与**通道封闭时段**（可添加多段起止秒数区间），同一对区域仅允许一条连接。
- **演员**：维护演员姓名与角色。
- **到位口令**：按「演员 + 目标区域 + 时间」下达口令，时间支持 `90`（秒）或 `01:30`（分:秒）两种输入格式；每条口令可设 **0～600 秒停留时长**（缺省 0，用于连续口令延误传导模式）。
- **校验结果**：对每位演员，将其口令按时间升序排列，逐边推演（时间依赖 Dijkstra）：
  - ✅ **按时**：最早到达时刻 ≤ 下一口令时刻，显示余量秒数、最早到达时刻与实际路线；
  - ❌ **超时**：最早到达时刻 > 下一口令时刻，红色高亮并显示「所需 X 秒 / 可用 Y 秒、缺口 Z 秒」；
  - ⛔ **不可达**：两区域在连接图上不连通（封闭时段只会造成等待或绕行，不会造成不可达）。
  - 🚶 **通道占用冲突**：结果区顶部汇总全部冲突事件，发生冲突的区段在路线旁逐条标记关联冲突。
- **延误传导展示**：连续口令延误传导模式下，结果区逐段列出**计划/实际出发时刻、实际到达、继承延误与最终迟到**，演员标题处给出传导链末端状态（最终迟到或「延误已全部吸收」）。
- **走位方案基线对比**：在当前校验模式下可将一次校验结果**保存为基线快照**；此后编辑区域、连接、演员或口令，结果区会**即时对比当前结果与基线**（无需手动刷新）：
  - 以「**演员 ID + 相邻口令 ID**」组成稳定区段键匹配，新增 / 删除 / 重排口令都不会按数组位置错配；结果区分组列出**新增区段**与**移除区段**；
  - **共有区段**逐项对比：按时 / 超时 / 不可达**状态**、**实际到达时刻**、**迟到秒数**、**实际路线**与**关联通道冲突**（冲突按「连接 + 超载时段」匹配，不依赖冲突序号）；
  - 顶部汇总徽章给出**状态转好 / 转差**、**迟到增减**、**通道冲突新增 / 解除**的区段计数；无差异时提示「与基线完全一致」；
  - 基线按校验模式分别保存：切换到另一种校验模式时，若该模式没有基线而另一模式存在，会**提示模式不一致且不做比较**（可一键清除另一模式的基线）；
  - 支持**覆盖**基线（用当前结果重新保存）与**清除**基线；基线随数据文件**持久化**（保存在数据文件的 `baselines` 字段中，恢复示例数据时一并清空）；
  - **导出的 Markdown 报告会追加同样的对比摘要**（基线信息、总体变化、汇总计数对比、新增 / 移除区段表与共有区段变化明细表）；当前模式没有基线时报告不包含该章节。
- **应急疏散快照**：在「应急疏散快照」卡片输入事件时刻并勾选一个或多个出口区域，系统按当前校验模式的实际路线还原每位演员当时的位置并计算最早疏散路线：
  - **位置还原**：逐边时间轴精确到秒——🚶 **通道行进中**（含所在通道、方向与剩余秒数）、⏱ **区域等待**（通道封闭等待 / 等待下一口令时刻）、🧍 **停留**（计划停留 / 走位结束后停留）；
  - **疏散计算**：位于通道者**先按原方向走完剩余路程**，再从到达区域按事件时刻之后的封闭时段（等待或绕行）计算到任一出口的最早路线；位于区域者从事件时刻直接计算；已位于出口区域者耗时为 0；
  - **位置未知**：因不可达链（区段不连通）或事件时刻早于走位时间轴而无法确定位置时，单独标为位置未知，**不做猜测**；
  - **结果展示**：按**最晚撤离优先**排序（无法疏散视为最晚），列出位置、出口、到达时刻、耗时与疏散路线；数据编辑或切换校验模式后快照随动重算；
  - **报告联动**：快照生成后，「导出校验报告」的 Markdown 会在文末追加同一快照。
- **跨演员口令依赖**：在「🔗 跨演员口令依赖」面板选择**前置口令**与**后置口令**（可属于不同演员）并设置 **0～3600 秒等待时长**，维护有向约束：
  - **保存前整图成环检查**：新增依赖会检查「已有依赖 + 新边」构成的整张依赖图，一旦**成环即拒绝写入**（返回 400 且不修改数据文件），错误信息包含**构成环的口令链**（演员 · 时刻 · 区域，首尾相接呈现闭环）；
  - **即时校验与随模式重算**：校验按**当前模式**的实际时刻计算——前置完成时刻 = 前置口令实际到达 + 停留时长，后置实际出发 = 为执行后置口令而离开上一口令的区段出发时刻；满足条件 `前置完成 + 等待秒数 ≤ 后置实际出发` 时标 **✅ 满足**（富余秒数），否则 **❌ 违约**（缺口秒数）；任一端口令在当前模式下不可达（或已删除）时标 **❓ 无法判定**；新增 / 删除依赖、编辑口令或切换模式后结果即时重算；
  - **级联清理**：删除口令时自动删除以其为前置或后置的全部依赖；删除演员 / 区域连带删除口令时同样清理相关约束；
  - **报告联动**：Markdown 报告追加「跨演员口令依赖校验」一节（汇总计数 + 全量明细表 + 违约 / 无法判定文字明细）。
- **等待展示**：结果区在路线下方逐边列出出发 / 到达时刻，并以 ⏱ 徽标标出**等待位置（区域）与时长**。
- **即时重算**：任何新增 / 编辑 / 删除操作（含封闭时段、停留时长编辑）保存后立即重新校验并刷新结果。
- **导出报告**：点击「导出校验报告」下载 Markdown 格式报告，与当前校验模式一致（含汇总表、**通道占用冲突汇总与明细**、**跨演员口令依赖汇总与明细**、每位演员的区段明细、**逐边动态路线明细**，传导模式下另附**延误传导明细**）。
- **级联一致性**：删除区域会同时删除相关连接与口令；删除演员会同时删除其全部口令；删除口令（或连带删除）会自动清理相关的跨演员口令依赖。

## 走位方案基线对比操作说明

1. 在结果区顶部用模式切换按钮选择校验模式（默认「连续口令延误传导」）。
2. 点击「**保存当前结果为基线**」，系统会对该模式保存一份基线快照（记录保存时间）。
3. 之后在下方任意面板新增 / 编辑 / 删除区域、连接、演员或口令，结果区顶部立即出现对比摘要：
   - 徽章：新增 / 移除区段数、状态转好 / 转差、迟到减少 / 增加、冲突新增 / 解除；
   - 明细：🟢 新增区段、🔴 移除区段、🟡 共有区段变化（状态、实际到达、迟到、路线、关联冲突的基线 → 当前对照）。
4. 想以当前方案为新基准时点「**覆盖基线**」；不再需要时点「**清除基线**」。
5. 切到另一种校验模式时：基线是**按模式分别保存**的。若另一模式存在基线而当前模式没有，顶部会黄色提示「模式不一致，不比较」——可按提示清除另一模式基线，或切回原模式继续查看；在当前模式另存基线即可单独比较。
6. 基线随数据持久化（Docker 命名卷 / `DATA_DIR` 内的数据文件），重启不丢失；「恢复示例数据」会同时清空基线。
7. 点击「📄 导出校验报告」下载的 Markdown 在汇总表之后追加「走位方案基线对比摘要」，内容与页面一致。

## 应急疏散快照操作说明

1. 启动服务后访问 **http://localhost:3000**（Docker Compose 默认将容器内 `3000` 端口映射到主机 `3000` 端口；本地 `npm start` 同样为 3000 端口，可用 `PORT` 环境变量修改）。
2. 在「校验结果」卡片顶部选择校验模式（快照按**当前模式**的实际路线还原位置）。
3. 在「🚨 应急疏散快照」卡片输入**事件时刻**（支持 `90` 秒或 `01:30` 分:秒两种格式），并勾选**一个或多个出口区域**，点击「**生成疏散快照**」。
4. 结果区按**最晚撤离优先**列出每位演员：事件时刻位置（区域等待 / 停留 / 通道行进中及剩余路程）、出口、到达时刻、耗时与疏散路线；**无法疏散**（位置已知但无任何出口可达）排最前，**位置未知**（不可达链或时间轴未开始，不猜测）单独列于文末。
5. 快照生成后：编辑区域 / 连接 / 演员 / 口令或切换校验模式，快照会按最新数据与当前模式**即时重算**；点击「清除快照」可收起结果并恢复报告为不含快照的版本。
6. 快照生成期间点击「📄 导出校验报告」，下载的 Markdown 会在文末追加**同一快照**（事件时刻、出口、最晚撤离时刻、快照表与位置未知名单）。

## 通道封闭时段规则

- 每条连接可维护 **0 至多段**封闭时段，每段为起止秒数区间 `[开始, 结束)`（**含开始、不含结束**），开始必须严格小于结束，均为不小于 0 的整数秒。
- 演员在时刻 `t` 进入一条通行耗时为 `w` 的连接时，占用区间为 `[t, t+w]`；若该区间与任一段封闭区间**重叠**（`t < 结束` 且 `t+w > 开始`），则此时刻不可进入。
- 冲突时演员在该连接**起点所在的区域内等待**，直至封闭结束（最早可进入时刻 = 封闭结束时刻；多段封闭会依次向后滚动计算）。
- 校验算法会比较「等待」与「绕行其他路径」两种方案，取**最早到达时刻**的路线作为实际路线；等待位置与时长会在结果区和报告中展示。
- 封闭时段为有限区间，因此只会推迟到达、不会影响图连通性；「不可达」仍仅表示区域间没有任何连接路径。
- 旧数据文件中没有封闭时段字段的连接按「无封闭」处理，完全兼容。

## 通道占用冲突规则

- 在两种走位模式（区段独立 / 连续口令延误传导）各自算出逐边路线**之后**，将所有演员对每条**无向连接**的占用按半开区间 **`[进入, 离开)`** 汇总：进入时刻 = 该边实际出发时刻，离开时刻 = 实际到达时刻。
- 每条连接有**容量**（同一时刻允许并发占用的人数），默认为 **1**，可在连接编辑中设为 **1～10** 的整数；旧数据文件中没有容量字段的连接按 1 处理。
- 任一时刻并发占用人数（按演员去重）**超过容量**即生成冲突事件；超载状态先消失再出现的区间会被切开，**首尾恰好相接的连续超载区间合并为一条**。冲突事件列出：所在通道、容量、起止时刻与持续秒数、**峰值人数**，以及每位参与演员的**方向、进入/离开时刻、关联区段**。
- **首尾恰好相接不算重叠**：一方离开时刻恰等于另一方进入时刻时，不构成并发（半开区间）。
- **等待时间不占用通道**：因封闭时段在前一区域等待的时段不计入任何连接的占用。
- 结果区顶部给出跨演员的冲突汇总与明细卡片；涉及冲突的区段在其路线旁标记关联冲突（通道、时刻、峰值/容量）。
- Markdown 报告在汇总表中新增「🚶 通道占用冲突」计数，并增加「通道占用冲突汇总」一节（汇总表 + 每条冲突的演员 / 方向 / 起止 / 关联区段明细）；各区段表与路线明细中标注关联冲突。
- 注意：冲突是对**已推演路线**的事后校验，不会改变演员的出发 / 到达时刻；两种模式算出的路线不同，冲突结果也随之不同。

## 连续口令延误传导规则

- 每条口令可维护 **0～600 秒**的停留时长（整数秒，缺省 0；旧数据文件中没有该字段的口令按 0 处理，完全兼容）。
- 对每位演员按口令时间升序**连续推演**：**首条口令视为准时到位**（实际到达 = 计划时刻）。
- 从某条口令前往下一条时，**实际出发时刻 = max（该条计划时刻，实际到达该条的时刻） + 该条停留时长**；随后复用封闭等待 / 绕行算法计算下一条口令的实际到达。
- 某段迟到会**传导**给后续区段（继承延误逐段累积）；若后续口令间隔充足，到达仍不晚于计划时刻，则**延误被吸收**、恢复准时，不再向后传导。
- 结果区逐段展示：计划出发（计划时刻 + 停留）、实际出发、实际到达、继承延误（到达本段起点时已晚的秒数）与最终迟到（到达终点口令时晚于计划的秒数）。
- 不可达区段无法计算实际到达，其后区段自下一口令的**计划时刻**重新起算（传导链中断处会在报告明细中注明）。
- 「区段独立校验」模式不使用停留时长，也不做延误传导，行为与旧版一致。

## 跨演员口令依赖规则

- 每条依赖为一条**有向约束**：前置口令 `preCueId` → 后置口令 `postCueId`，等待秒数 `waitSeconds` 为 **0～3600 的整数秒**；前置与后置可以属于**不同演员**（也可同一演员），但不能是同一条口令；同一对口令之间只允许一条依赖（重复添加返回 409）。
- **判定公式**：`前置完成时刻 + waitSeconds ≤ 后置实际出发时刻`。
  - **前置完成时刻** = 前置口令在**当前校验模式**下的**实际到达时刻** + 该口令的**停留时长**（两种模式下停留时长均计入完成时刻）；
  - **后置实际出发时刻** = 为执行后置口令而**离开上一口令的区段出发时刻**（即以后置口令为终点的区段的实际出发；演员的首条口令取其计划时刻，因为无需移动即到位）；
  - 在「连续口令延误传导」模式下两端时刻均包含封闭等待 / 绕行与逐段传导的实际结果；在「区段独立校验」模式下区段出发取前置口令计划时刻、实际到达按独立推演计算。
- **结论**：
  - ✅ **满足**：不等式成立，`相差 = 后置实际出发 - 最早允许出发` 为富余秒数；
  - ❌ **违约**：不等式不成立，相差为负数，其绝对值即**缺口秒数**；
  - ❓ **无法判定**：前置或后置口令在当前模式下不可达（连接图不连通），实际完成 / 出发时刻未知，不做猜测；口令已删除同样标为无法判定。
- **成环检查（保存前）**：新增依赖时在「已有依赖 + 候选新边」的整张有向图上做环检测；成环则返回 **400**（响应体含 `cycle`：构成环的口令 ID 链，`chain`：可读口令链），**不写入数据文件**。已有依赖图若因数据异常已含环，校验会照常评估各条依赖。
- **删除与级联**：可随时删除单条依赖；删除口令时级联删除引用它的全部依赖；删除演员 / 区域连带删除口令时同样清理。
- 依赖校验是对**已推演走位结果**的事后校验，不改变任何出发 / 到达时刻；两种模式结果不同，依赖结论随之变化；依赖不参与基线对比的差异计算，但随数据一起持久化。

## 应急疏散快照规则

- **位置还原**：以当前校验模式（区段独立 / 连续口令延误传导）已推演的逐边实际路线为唯一依据，将每位演员的走位展开为覆盖「首条口令时刻 → 之后」的时间轴，定位事件时刻所在区间：
  - 🚶 **通道行进中**：事件时刻落在某条连接的占用区间 `[进入, 离开)` 内；
  - ⏱ **区域等待**：在区域内等待封闭时段结束，或早到后等待下一口令计划时刻；
  - 🧍 **停留**：口令的计划停留时长内，或全部口令完成后停留在最终区域。
- **位于通道者**：先按原方向走完剩余路程（抵达时刻 = 该边实际到达时刻），再从到达区域计算疏散路线；区段独立模式下若后段口令按计划时刻重新起算导致位置窗口被截断，剩余路程仍以该边**真实抵达时刻**为准。
- **位于区域者**：从所在区域、事件时刻直接计算疏散路线；已位于出口区域者到达时刻即事件时刻、耗时 0。
- **疏散路线**：复用时间依赖 Dijkstra，在全部所选出口中取**到达时刻最早**者；事件时刻之后的封闭时段仍会造成等待或绕行（与走位校验同一套规则）。
- **位置未知**：事件时刻处于不可达区段（连接图不连通）期间、早于首条口令时刻、或演员没有口令时，单独标为位置未知，**不猜测**其位置；连续口令延误传导模式下，不可达区段自下一口令计划时刻起按该模式的重算规则恢复可知。
- **无法疏散**：位置已知但没有任何出口可达（如处于无连接的孤立区域），视为最晚撤离，排在结果最前。
- **排序**：结果按最晚撤离优先（无法疏散 → 到达时刻降序），位置未知者不参与排序、单独列出。
- 快照不修改任何走位数据，也不参与通道占用冲突与基线对比的计算；报告中的快照与页面为同一次计算结果。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/data` | 获取全部数据（区域 / 连接 / 演员 / 口令 / 跨演员口令依赖） |
| GET | `/api/validate?mode=…` | 执行走位校验；`mode` 为 `classic`（区段独立，缺省）或 `propagate`（连续口令延误传导），返回区段级结果（含最早到达时刻、逐边路线与等待明细；传导模式另含计划/实际出发、继承延误、最终迟到）；顶层 `conflicts` 为通道占用冲突事件列表，`summary.conflicts` 为冲突计数，相关区段上带 `conflicts` 关联标记；顶层 `dependencies` 为跨演员口令依赖校验结果（`items` 含每条依赖的前置完成、后置实际出发、最早允许出发、相差秒数与 `satisfied` / `violated` / `unknown` 状态，`summary.dependencies` 为计数）。结果另含：`baseline`（当前模式基线元信息）、`baselines`（两种模式的基线元信息）、`comparison`（当前模式存在基线时的对比摘要，否则为 `null`） |
| GET | `/api/evacuation?mode=…&time=…&exits=…` | 应急疏散快照：`time` 为事件时刻（不小于 0 的整数秒），`exits` 为逗号分隔的出口区域 ID（至少一个）；按 `mode` 的实际路线还原每位演员位置并计算到任一出口的最早疏散路线。返回 `entries`（按最晚撤离优先排序，含位置、出口、到达时刻、耗时与逐边路线；无法疏散者 `status` 为 `unreachable`）、`unknown`（位置未知名单及原因）与 `summary`（含最晚撤离到达时刻 `latestArrival`） |
| GET | `/api/report?mode=…` | 下载 Markdown 校验报告（`mode` 含义同上，含通道占用冲突汇总与明细；传导模式报告另含延误传导明细）；当前模式已保存基线时追加「走位方案基线对比摘要」；可选附加 `time` 与 `exits` 参数（含义同上），同时在报告末尾追加同一份「应急疏散快照」 |
| POST | `/api/baseline/:mode` | 保存（或覆盖）指定模式（`classic` / `propagate`）的基线快照，基线随数据持久化 |
| DELETE | `/api/baseline/:mode` | 清除指定模式基线；`:mode` 传 `all` 清除全部模式基线 |
| POST | `/api/dependencies` | 新增跨演员口令依赖，请求体 `{ preCueId, postCueId, waitSeconds }`；保存前整图成环检查，成环返回 400（含 `cycle` 口令 ID 链与 `chain` 可读链）且不写入；重复边返回 409 |
| DELETE | `/api/dependencies/:id` | 删除指定跨演员口令依赖；删除口令（含删除演员 / 区域连带删除）时由服务端级联清理相关依赖 |
| POST | `/api/reset` | 恢复内置示例数据（同时清空全部基线） |
| POST / PUT / DELETE | `/api/areas`、`/api/edges`、`/api/actors`、`/api/cues`（`/:id`） | 四类资源的增改删 |

`edges` 的创建 / 更新请求体示例：

```json
{
  "a": "area-wing-r",
  "b": "area-center",
  "seconds": 4,
  "capacity": 1,
  "closures": [ { "start": 10, "end": 14 }, { "start": 30, "end": 36 } ]
}
```

`closures` 可省略（等价于无封闭）；每段需满足 `0 ≤ start < end` 且为整数秒，否则返回 400。

`capacity`（通道容量）可省略：创建时缺省为 `1`，更新时不传则保留原值；需为 `1～10` 的整数秒，否则返回 400。旧数据文件中没有该字段的连接按容量 1 处理，完全兼容。

`cues` 的创建 / 更新请求体示例：

```json
{
  "actorId": "actor-zhang",
  "areaId": "area-center",
  "time": 20,
  "dwell": 8,
  "note": "上台亮相"
}
```

`dwell`（停留时长）可省略，缺省为 `0`；需为 `0～600` 的整数秒，否则返回 400。更新时不传 `dwell` 则保留原值。

`dependencies`（跨演员口令依赖）的创建请求体示例：

```json
{
  "preCueId": "cue-l2",
  "postCueId": "cue-z4",
  "waitSeconds": 5
}
```

`waitSeconds` 需为 `0～3600` 的整数秒；两端必须都是已存在的不同口令。保存前会检查整张依赖图：成环返回 400，响应体形如 `{ "error": "…", "cycle": ["cue-a", "cue-b"], "chain": "演员 00:20 区域 → … → 演员 00:20 区域" }`，且数据不写入。

## 项目结构

```
├── server.js            # Express 入口
├── src/
│   ├── store.js         # JSON 文件持久化 + 示例数据初始化（含基线存储）
│   ├── graph.js         # 时间依赖推演：封闭时段等待 / 绕行 + 最早到达（Dijkstra）
│   ├── conflicts.js     # 通道占用冲突：按无向连接汇总 [进入,离开) 占用、容量校验、连续超载合并
│   ├── validate.js      # 走位校验核心逻辑（simulateActor 逐段推演为校验与疏散快照共用事实来源；汇总跨演员口令依赖时刻索引）
│   ├── dependencies.js  # 跨演员口令依赖：整图成环检测（含口令链）与满足 / 违约 / 无法判定评估
│   ├── evacuation.js    # 应急疏散快照：还原事件时刻位置（等待 / 停留 / 通道）、剩余路程接驳、最早疏散路线
│   ├── baseline.js      # 基线对比：演员 ID + 相邻口令 ID 稳定键匹配，状态 / 到达 / 迟到 / 路线 / 冲突差异
│   ├── report.js        # Markdown 报告生成（含基线对比摘要、冲突汇总明细、依赖汇总明细、动态路线明细与疏散快照）
│   └── routes.js        # REST API 路由与入参校验（含基线保存 / 覆盖 / 清除、依赖新增 / 删除 / 成环拦截与级联清理、疏散快照）
├── public/              # 前端（原生 HTML/CSS/JS）
├── seed/sample-data.json# 内置示例数据（含封闭时段演示）
├── Dockerfile
└── docker-compose.yml
```
